# 서버 운영 시간(시간표)

서버마다 열려 있는 시간을 정해 두면, 게이트가 그 시간에 맞춰 서버를 **켜고 끕니다.**
정하는 곳은 게이트 설정(`/home/dev/servers/bweeep-gate/<유닛>.json`) 한 곳뿐입니다. 시간표가 없으면 지금처럼 항상 열려 있고, 게이트는 아무것도 스스로 하지 않습니다.

게이트가 하는 일:

1. **시간이 끝날 때:** 서버가 켜져 있으면 게임 안에 알림을 띄우고(5분 전, 1분 전, 10초 전) 콘솔 `stop`으로 **월드를 저장하며** 끕니다. 강제 종료(`kill -9`)는 쓰지 않습니다.
2. **시간이 시작할 때:** 꺼져 있으면 켭니다. 그 뒤로는 평소와 같습니다(10분 비면 잠들고, 열려 있는 동안은 접속하면 깨어남).
3. **시간 밖:** 꺼진 서버는 켜지 않습니다. 접속은 "지금은 열려 있지 않아요. 금 12:00에 열려요"로 거절하고, 런처는 시작 버튼을 막습니다.

## 설정 모양

```json
"schedule": {
  "startsOn": "2026-10-23",
  "open": [{ "from": "fri 12:00", "to": "sun 12:00" }],
  "warn": true
}
```

- 시간은 모두 **한국 시간**입니다(서머타임 없음).
- `from` 이상 `to` 미만이 열려 있습니다. `to` 가 더 앞이면 주를 넘어 이어집니다(`"sun 12:00"` → `"fri 12:00"`).
- `startsOn` (한국 날짜, 선택): 이 날짜 전에는 항상 열려 있고 게이트는 아무것도 하지 않습니다. `startsOn` 자체는 "끄는 시각"이 아닙니다: 그날 서버가 켜져 있으면 첫 시간대가 끝날 때까지 그대로 둡니다(코블몬 테스트 기간을 자정에 끊지 않으려는 것).
- `warn` (선택, 기본 `true`): `false` 면 끄기 전 알림을 보내지 않습니다.
- `open` 은 1~14개, 요일은 `mon tue wed thu fri sat sun`. 알 수 없는 항목이나 잘못된 시각이 있으면 게이트가 시작하지 않고 이유를 말합니다(`show` 로 먼저 확인하세요).

## 지금 정해 둔 시간

`scripts/gate-schedule.mjs` 맨 위의 상수가 전부입니다.

| 상수 | 값 | 뜻 |
|---|---|---|
| `OPEN_HOUR` | `12:00` | 금·일 "오후" 경계. 사용자가 정확한 시각을 말하지 않아 낮 12시로 둔 **임시 값**입니다 |
| `STARTS_ON` | `2026-10-23` | 시간표가 시작되는 첫 금요일. "2주 후 오픈"을 2026-10-09~11 주말 기준으로 읽은 **추정**입니다 |
| `STANDARD_HOURS` | 아래 | 유닛별 시간대 |

- 코블몬 `bweeep-cobblemon-fabric`: 금 12:00 → 일 12:00
- 선릿벨리 `bweeep-society-server`: 일 12:00 → 금 12:00

두 서버는 겹치지도 비지도 않습니다(검증 스크립트가 3주치를 1분 단위로 확인합니다). 고칠 곳은 이 한 줄들뿐입니다.

## 알림·간격을 바꾸려면 (`scripts/server-gate.mjs` 맨 위)

| 이름 | 값 | 뜻 |
|---|---|---|
| `HOURS_WARNINGS` | 5분 전 "5분 뒤 서버가 닫혀요", 1분 전 "1분 뒤 서버가 닫혀요", 10초 전 "곧 서버가 닫혀요, 지금 저장돼요"(긴급) | 시각과 문구. 게임 안 배너(`bweeep.notice`)로 RCON 을 통해 보냅니다 |
| `DEFAULTS.openStartDelayMs` | 60초 | 시간이 시작된 뒤 이만큼 기다렸다가 켭니다. 같은 순간에 닫히는 서버(코블몬 일 12:00 = 선릿벨리 일 12:00)가 저장하고 나갈 시간을 줍니다. 다른 게이트가 끄는 중이면(`<유닛>.stopping` 표시) 그것이 끝날 때까지도 기다립니다 |
| `DEFAULTS.startFreshMs` | 10분 | 이보다 오래된 "시작 시각"은 따르지 않습니다(그때 게이트가 없었다면, 쉬는 서버를 그대로 쉬게 둠) |
| `DEFAULTS.warningLateMs` | 15초 | 알림은 제시각에서 이 안에서만 보냅니다(늦은 "5분 뒤"는 거짓말이 되므로) |
| `DEFAULTS.lateCloseWaitMs` | 10초 | 끝낼 때를 늦게 발견했을 때(게이트 재시작, 시간표 새로 읽음, 손으로 연 시간이 끝남) 마지막 알림을 띄우고 이만큼 기다린 뒤 끕니다 |

## 동작표

| 상황 | 게이트 | 런처 |
|---|---|---|
| 시간 안, 꺼져 있음 | 지금처럼 접속하면 깨움 | 지금처럼 |
| 시간이 시작됨 | 60초 뒤(그리고 다른 서버가 다 꺼진 뒤) 서버를 켬. 한 번만 | 켜지는 중 → 켜짐 |
| 시간 안, 접속자 없음 10분 | 지금처럼 잠듦. 시작 경계로 다시 켜지는 일은 없음 | 쉬는 중 |
| 시간 끝 5분·1분·10초 전, 서버 켜짐 | 게임 안 알림 | — |
| 시간이 끝남, 서버 켜짐 | 콘솔 `stop`으로 저장하고 끔(안 되면 systemd 의 정상 종료). 한 번만 | 닫힘 |
| 시간 밖, 꺼져 있음 | 켜지 않음. 접속 "지금은 열려 있지 않아요. 금 12:00에 열려요", 상태는 `closed` + `nextOpen` | 상단 바 "금 12:00 열림", 시작 버튼 위 한 줄, 시작 버튼 비활성. 메인 프로세스도 같은 답이면 거절 |
| 시간 밖인데 게이트가 (재)시작되고 서버가 켜져 있음 | 마지막 알림을 띄우고 10초 뒤 끔. 이 경계에 대해 한 번만(게이트가 다시 시작돼도 `<유닛>.hours.json` 에 기억) | — |
| 끄는 중에 접속 | 거절, 다 꺼진 뒤 다시 켜지도 않음 | — |
| 관리자가 손으로 열어 둠(`open --hours`) | 그 시간이 끝날 때까지 자동으로 아무것도 안 함. 끝나면 보통의 "시간이 끝남" 순서(5분 전 알림부터) | 열린 서버 |
| `startsOn` 전, 시간표 없음 | 아무것도 안 함 | 지금처럼 |
| 누가 닫힌 시간에 손으로 켬 | 그 경계는 이미 처리됐으므로 그냥 둠(끄고 켜기를 되풀이하지 않음) | — |

참고: 게이트가 먹통이 된 서버를 다시 시작하는 `recover` 는 그대로입니다. 게이트가 응답하지 않거나 시간 정보가 없거나 옛 게이트면 런처는 지금처럼 동작합니다(상태를 못 읽었다고 사람을 막지 않음).

## 관리자가 닫힌 서버를 켜야 할 때(테스트 등)

런처 버튼은 닫힘이면 누구에게나 막힙니다(게이트가 사용자 권한을 알 방법이 없습니다). 대신 게이트 쪽에서 손으로 엽니다.

```
node scripts/gate-schedule.mjs open --config /home/dev/servers/bweeep-gate/<유닛>.json --hours 3          # 미리보기
node scripts/gate-schedule.mjs open --config /home/dev/servers/bweeep-gate/<유닛>.json --hours 3 --write  # 3시간 동안 열림
node scripts/gate-schedule.mjs close-by-hand --config ... --write                                            # 끝내기
```

`close-by-hand` 로 끝내면 닫힌 시간에 켜져 있는 서버는 마지막 알림 뒤 꺼집니다.

## 운영에 켜는 순서(아직 하지 않았습니다)

게이트 프로세스는 코드를 시작할 때만 읽고, 접속이 전부 게이트를 거치므로 **게이트를 다시 시작하면 그 사람들의 접속이 끊깁니다.** 그리고 **시간표를 읽는 순간 게이트는 지금 시각 기준으로 할 일을 합니다** — 닫힌 시간에 서버가 켜져 있으면 끕니다. 그래서 아래 순서를 지킵니다. `startsOn` 이 오기 전에는 아무 일도 일어나지 않으므로 2026-10-23 전, 서버가 비었을 때 해 두면 됩니다.

1. 확인만: `node scripts/gate-schedule.mjs show --config /home/dev/servers/bweeep-gate/bweeep-cobblemon-fabric.json` (시간표는 아직 없음)
2. 새 게이트 코드 깔기, **서버가 비었을 때만**: `install --config <gate.json>` 로 미리보기 → 접속자가 있으면 스스로 멈춥니다 → 비면 `--write`. 유닛마다 한 번씩(코블몬, 선릿벨리). 옛 게이트는 시간표를 모르는 코드라 이 단계에서 시간표는 아직 적용되지 않습니다.
3. 시간표 쓰기: `apply --config <gate.json>` 미리보기 → `--write` (백업 `gate.json.bak-<시각>` 자동).
4. 이미 새 코드로 돌고 있는 게이트에 읽히기: `reload --config <gate.json>` 가 "게이트가 지금 시간표를 읽으면 할 일"을 먼저 보여 줍니다(예: "서버가 켜져 있어 경고 후 끕니다") → 괜찮으면 `--write` (SIGHUP, 접속은 끊기지 않음). 2번에서 막 다시 시작했다면 이미 읽은 상태입니다.
5. 확인: `show --config <gate.json> --at 2026-10-27T10:00+09:00` 처럼 미래 시각을 넣어 동작을 미리 봅니다.
6. 런처: 이 PR이 병합돼 릴리스된 뒤부터 버튼이 막힙니다. 옛 런처는 닫힌 서버를 "열린 서버"로 보여 주지만, 게이트가 켜지 않고 접속도 거절합니다.

되돌리기: `clear --config <gate.json> --write` 뒤 `reload --write`. 또는 `gate.json.bak-…` 를 되돌리고 `reload`. 시간표를 지우면 게이트는 더 이상 아무것도 스스로 하지 않습니다.

## 검증

`node scripts/verify-server-schedule.mjs`: 시간 계산·경계·주 넘김·한국 시간·엄격한 설정 검사, 가짜 서버와 가짜 콘솔로 하는 게이트 시나리오(알림 후 끄기 한 번, 시작 한 번, 게이트 재시작, 손으로 연 시간, `startsOn` 전, 시간표 없음, 동시에 닫히고 열리는 두 서버의 순서, 콘솔이 안 될 때 systemd 정상 종료로 대체), 도구, 실제 게이트 프로세스의 SIGHUP.
`node scripts/verify-server-gate.mjs`, `node scripts/verify-server-status.mjs`, 런처 화면은 `BWEEP_PREVIEW_SERVER_CLOSED=true node scripts/capture-preview.mjs`.
